📖 Introducción

¿Qué es un Transformer Encoder?

Un Transformer Encoder es una arquitectura de red neuronal basada en mecanismos de atención multi-cabeza que fue introducida en el paper "Attention is All You Need" (Vaswani et al., 2017). A diferencia de las redes convolucionales (CNNs), los Transformers procesan secuencias completas en paralelo, permitiendo que cada elemento de la secuencia atienda a todos los demás elementos.

✓ Ventajas del Transformer Encoder
  • Paralelización: Procesa toda la secuencia simultáneamente, no secuencialmente
  • Atención Global: Cada posición puede relacionarse con cualquier otra posición
  • Menor Sesgo Inductivo: No asume ninguna estructura especial en los datos
  • Escalabilidad: Se puede entrenar con secuencias muy largas

Aplicaciones Reales

El Transformer Encoder es la base de modelos populares como:

  • BERT - Para procesamiento de lenguaje natural
  • ViT (Vision Transformer) - Para clasificación de imágenes
  • Wav2Vec 2.0 - Para procesamiento de audio
  • En nuestro caso: Clasificación de sonidos urbanos

Objetivo del Proyecto

En este proyecto, implementamos un Transformer Encoder para clasificar automáticamente sonidos urbanos del dataset Urban Sound 8K en una de 10 categorías diferentes. El modelo procesa características MFCC (Mel Frequency Cepstral Coefficients) extraídas de archivos de audio para entender patrones temporales y realizar predicciones en tiempo real.

Extracción de Características MFCC

MFCC (Mel Frequency Cepstral Coefficients) son características que simulan cómo el oído humano percibe el sonido. Son especialmente útiles para clasificación de audio porque:

  • Están basadas en la escala Mel, que refleja cómo los humanos perciben frecuencias
  • Capturan información relevante del espectro de frecuencias
  • Son mucho más compactas que el audio crudo
  • Reducen el ruido irrelevante para la clasificación

Proceso de Extracción (en el código):

# Cargar audio con frecuencia de muestreo 22050 Hz
y, sr = librosa.load(file_path, sr=22050)

# Extraer 13 coeficientes MFCC
mfcc = librosa.feature.mfcc(y=y, sr=sr, n_mfcc=13)

# Transponer: (n_mfcc, tiempo) → (tiempo, n_mfcc)
mfcc = mfcc.T

# Normalización z-score por cada coeficiente
mfcc = (mfcc - mfcc.mean(axis=0, keepdims=True)) / (mfcc.std(axis=0, keepdims=True) + 1e-8)

# Hacer todas las muestras de longitud fija: 200 pasos de tiempo
if mfcc.shape[0] < max_time_steps:
    padding = np.zeros((max_time_steps - mfcc.shape[0], n_mfcc))
    mfcc = np.vstack([mfcc, padding])
else:
    mfcc = mfcc[:max_time_steps, :]
ℹ️ Formato de Datos
  • Entrada del Modelo: Tensor de forma (batch_size, seq_len, n_mfcc) = (96, 128, 13)
  • Salida del Modelo: Logits de forma (batch_size, num_classes) = (96, 10)
  • Normalización: Cada coeficiente MFCC está normalizado independientemente
  • Padding: Para audios cortos se añaden ceros; para audios largos se truncan

🏗️ Arquitectura del Modelo

Componentes Principales

INPUT MFCC (128, 13) ↓ EMBEDDING Linear: 13 → 128 ↓ POSITIONAL ENCODING Suma de embeddings + posiciones ↓ TRANSFORMER BLOCK 1 ├─ MultiHeadAttention (6 heads) ├─ LayerNorm + Residual ├─ MLP (128 → 512 → 128) └─ LayerNorm + Residual ↓ TRANSFORMER BLOCK 2 (Idem al anterior) ↓ MEAN POOLING Promedio sobre eje temporal ↓ CLASSIFICATION HEAD ├─ LayerNorm ├─ Dropout └─ Linear: 128 → 10 clases ↓ OUTPUT LOGITS (10)

1. Embedding + Positional Encoding

¿Por qué necesitamos embedding?

  • Los MFCCs tienen dimensión 13, pero el modelo trabaja con dimensión 128 (n_embd)
  • El embedding proyecta los datos a este espacio latente más grande

¿Por qué necesitamos positional encoding?

  • El mecanismo de atención es agnóstico al orden de los elementos
  • Sin información de posición, [A, B] sería idéntico a [B, A]
  • El positional encoding añade información sobre la posición temporal de cada frame MFCC
# Embedding
self.inp_emb = torch.nn.Linear(n_input=13, n_embd=128)

# Positional Encoding (aprende durante el entrenamiento)
self.pos_emb = torch.nn.Parameter(torch.zeros(1, seq_len=128, n_embd=128))

# Forward pass
e = self.inp_emb(x) + self.pos_emb  # Suma elemento a elemento
e = self.dropout(e)

2. Multi-Head Attention

¿Cómo funciona la atención?

La atención calcula una suma ponderada de los valores (V) basada en la similitud entre queries (Q) y keys (K):

Attention(Q, K, V) = softmax(Q·K^T / √d_k)·V

¿Qué es "Multi-Head"?

En lugar de aplicar atención una vez, aplicamos múltiples veces en paralelo (6 heads). Cada "head" atiende a diferentes aspectos de los datos:

  • Head 1: Podría enfocarse en cambios rápidos (altas frecuencias)
  • Head 2: Podría enfocarse en patrones lentos (bajas frecuencias)
  • Head 3-6: Otros patrones importantes
class MultiHeadAttention(torch.nn.Module):
    def forward(self, x):
        B, L, F = x.size()  # Batch, Length, Features
        
        # Proyectar a (B, L, n_heads*F)
        k = self.key(x).view(B, L, F, self.n_heads).transpose(1, 3)
        q = self.query(x).view(B, L, F, self.n_heads).transpose(1, 3)
        v = self.value(x).view(B, L, F, self.n_heads).transpose(1, 3)
        
        # Calcular atención para cada head
        att = (q @ k.transpose(-2, -1)) * (1.0 / math.sqrt(k.size(-1)))
        att = torch.nn.functional.softmax(att, dim=-1)
        y = att @ v
        
        # Combinar heads
        y = y.transpose(1, 2).contiguous().view(B, L, F*self.n_heads)
        return self.proj(y)

3. Transformer Block

Un bloque Transformer es la unidad fundamental. Consiste en:

┌─────────────────────────────┐ │ ENTRADA (seq_len, n_embd) │ └──────────────┬──────────────┘ ↓ ┌─ MultiHeadAttention ─┐ │ (6 heads, 128 dims) │ └──────┬───────────────┘ ↓ ┌─ Dropout (0.4) ──┐ └──────┬────────────┘ ↓ Residual Connection (+) ↓ ┌─ LayerNorm ──┐ └──────┬────────┘ ↓ ┌─ MLP ────────────────┐ │ 128 → 512 → 128 │ │ (4x expansion) │ └──────┬───────────────┘ ↓ ┌─ Dropout (0.4) ──┐ └──────┬────────────┘ ↓ Residual Connection (+) ↓ ┌─ LayerNorm ──┐ └──────┬────────┘ ↓ ┌─ SALIDA (seq_len, n_embd) ─┐ └─────────────────────────────┘ 
class TransformerBlock(torch.nn.Module):
    def forward(self, x):
        # Atención con residual y normalización
        x = self.ln1(x + self.dropout1(self.attn(x)))
        
        # MLP con residual y normalización
        x = self.ln2(x + self.dropout2(self.mlp(x)))
        return x
⚠️ Conexiones Residuales

Las conexiones residuales (skip connections) son cruciales para entrenar modelos profundos. Permiten que el gradiente fluya directamente a través de capas, evitando el problema del gradiente que desaparece.

4. Clasificación Final

Después de pasar por los bloques Transformer, tenemos una secuencia de 128 embeddings. Para hacer la clasificación en 10 clases, utilizamos:

  • Mean Pooling: Promediamos todos los embeddings temporales a uno solo
  • Classification Head: MLP que mapea el embedding promediado a 10 scores
# Después de transformer
x = self.transformer(e)  # Shape: (B, 128, 128)

# Mean pooling sobre la dimensión temporal
x_pooled = x.mean(dim=1)  # Shape: (B, 128)

# Classification head
logits = self.fc(x_pooled)  # Shape: (B, 10)
predictions = torch.argmax(logits, dim=1)  # Shape: (B,)

💻 Implementación Detallada

1. UrbanSoundDataset

La clase UrbanSoundDataset hereda de torch.utils.data.Dataset y se encarga de cargar y procesar archivos de audio individuales:

class UrbanSoundDataset(torch.utils.data.Dataset):
    def __init__(self, metadata_path, audio_dir, n_mfcc=13, sr=22050, max_time_steps=200):
        # Cargar metadatos CSV
        self.metadata = pd.read_csv(metadata_path)
        self.audio_dir = Path(audio_dir)
        self.n_mfcc = n_mfcc           # 13 coeficientes MFCC
        self.sr = sr                    # Sample rate: 22050 Hz
        self.max_time_steps = max_time_steps  # Longitud fija
    
    def __len__(self):
        # Número total de muestras
        return len(self.metadata)
    
    def __getitem__(self, idx):
        # Cargar una muestra individual
        row = self.metadata.iloc[idx]
        file_path = self.audio_dir / f"fold{row['fold']}" / row['slice_file_name']
        
        try:
            # 1. Cargar archivo de audio
            y, sr = librosa.load(file_path, sr=self.sr)
            
            # 2. Extraer MFCC
            mfcc = librosa.feature.mfcc(y=y, sr=sr, n_mfcc=self.n_mfcc)
            mfcc = mfcc.T  # (n_mfcc, tiempo) → (tiempo, n_mfcc)
            
            # 3. Normalizar
            mfcc = (mfcc - mfcc.mean(axis=0, keepdims=True)) / (mfcc.std(axis=0, keepdims=True) + 1e-8)
            
            # 4. Hacer longitud fija (pad o truncate)
            if mfcc.shape[0] < self.max_time_steps:
                padding = np.zeros((self.max_time_steps - mfcc.shape[0], self.n_mfcc))
                mfcc = np.vstack([mfcc, padding])
            else:
                mfcc = mfcc[:self.max_time_steps, :]
            
            # 5. Convertir a tensor
            mfcc = torch.tensor(mfcc).float()
            label = torch.tensor(row['classID']).long()
            return mfcc, label
        except:
            # En caso de error, retornar tensor vacío
            return torch.zeros(self.max_time_steps, self.n_mfcc).float(), torch.tensor(0).long()

2. UrbanSoundDataModule (PyTorch Lightning)

La clase UrbanSoundDataModule maneja la carga de datos usando PyTorch Lightning, que automáticamente gestiona el data loading de manera eficiente:

class UrbanSoundDataModule(pl.LightningDataModule):
    def __init__(self, metadata_path, audio_dir, batch_size=32, test_fold=5):
        super().__init__()
        self.metadata_path = metadata_path
        self.audio_dir = audio_dir
        self.batch_size = batch_size
        self.test_fold = test_fold  # Usar fold 5 como test
    
    def setup(self, stage=None):
        # Crear dataset completo
        full_dataset = UrbanSoundDataset(self.metadata_path, self.audio_dir)
        metadata = pd.read_csv(self.metadata_path)
        
        # Split: 80% train, 20% test
        train_idx = metadata[metadata['fold'] != self.test_fold].index
        test_idx = metadata[metadata['fold'] == self.test_fold].index
        
        # Crear subsets
        self.train_ds = torch.utils.data.Subset(full_dataset, train_idx)
        self.val_ds = torch.utils.data.Subset(full_dataset, test_idx)
    
    def train_dataloader(self):
        return DataLoader(self.train_ds, batch_size=self.batch_size, shuffle=True, num_workers=0)
    
    def val_dataloader(self):
        return DataLoader(self.val_ds, batch_size=self.batch_size, num_workers=0)

3. UrbanSoundModel (Transformer Encoder)

El modelo principal que integra todos los componentes:

class UrbanSoundModel(pl.LightningModule):
    def __init__(self, n_input=13, n_embd=128, seq_len=128, n_heads=6, n_layers=2, dropout=0.4, weight_decay=5e-4):
        super().__init__()
        self.seq_len = seq_len
        self.n_embd = n_embd
        self.weight_decay = weight_decay
        
        # EMBEDDING + POSITIONAL ENCODING
        self.inp_emb = torch.nn.Linear(n_input, n_embd)
        self.pos_emb = torch.nn.Parameter(torch.zeros(1, seq_len, n_embd))
        self.dropout = torch.nn.Dropout(dropout)
        
        # TRANSFORMER BLOCKS
        self.transformer = torch.nn.Sequential(
            *[TransformerBlock(n_embd, n_heads, dropout=dropout) for _ in range(n_layers)]
        )
        
        # CLASSIFICATION HEAD
        self.fc = torch.nn.Sequential(
            torch.nn.LayerNorm(n_embd),
            torch.nn.Dropout(dropout),
            torch.nn.Linear(n_embd, 10)
        )
    
    def forward(self, x):
        B = x.size(0)
        
        # Pad o truncate a seq_len
        if x.size(1) < self.seq_len:
            pad_len = self.seq_len - x.size(1)
            x = torch.nn.functional.pad(x, (0, 0, 0, pad_len))
        else:
            x = x[:, :self.seq_len, :]
        
        # EMBEDDING + POSITIONAL ENCODING
        e = self.inp_emb(x) + self.pos_emb
        e = self.dropout(e)
        
        # TRANSFORMER
        x = self.transformer(e)
        
        # MEAN POOLING + CLASSIFICATION
        y = self.fc(x.mean(dim=1))
        return y

4. Métodos de Entrenamiento

def training_step(self, batch, batch_idx):
    loss, acc = self.compute_loss_and_acc(batch)
    self.log('train_loss', loss, prog_bar=True, on_step=True, on_epoch=True)
    self.log('train_acc', acc, prog_bar=True, on_step=False, on_epoch=True)
    return loss

def validation_step(self, batch, batch_idx):
    loss, acc = self.compute_loss_and_acc(batch)
    self.log('val_loss', loss, prog_bar=True)
    self.log('val_acc', acc, prog_bar=True)

def configure_optimizers(self):
    optimizer = torch.optim.Adam(self.parameters(), lr=0.0004, weight_decay=5e-4)
    scheduler = torch.optim.lr_scheduler.CosineAnnealingLR(optimizer, T_max=15, eta_min=1e-6)
    return [optimizer], [{"scheduler": scheduler, "interval": "epoch"}]

Técnicas de Regularización

🔑 Técnicas para Evitar Overfitting
  • Dropout (0.4): Desactiva aleatoriamente neuronas durante entrenamiento
  • Weight Decay (5e-4): Penaliza pesos grandes en la función de pérdida
  • Early Stopping: Detiene entrenamiento cuando val_loss no mejora
  • Cross-Fold Validation: Usa fold 5 como test, resto como train
  • LayerNorm: Normaliza activaciones en cada capa

Métricas Monitoreadas

  • train_loss: Cross-entropy loss en datos de entrenamiento
  • train_acc: Precisión en datos de entrenamiento
  • val_loss: Cross-entropy loss en datos de validación
  • val_acc: Precisión en datos de validación (métrica principal)
⚠️ ¿Qué indica el diferencia entre train_acc y val_acc?
  • val_acc << train_acc: Posible overfitting. Solución: aumentar dropout, weight decay, o usar más datos
  • val_acc ≈ train_acc: Buen balance. El modelo generaliza bien
  • Ambas bajas: Underfitting. Solución: modelo más grande, entrenar más épocas, mejor hyperparameter tuning

¿Qué es el mecanismo de atención?

La atención es un mecanismo que permite que el modelo se enfoque en diferentes partes de la entrada según su importancia. Matemáticamente:

Attention(Q, K, V) = softmax(Q·K^T / √d_k)·V

  • Q (Query): "¿Qué quiero saber?"
  • K (Key): "¿Qué puedo ofrecer?" - Se compara con Query
  • V (Value): "Aquí está la información actual"
  • softmax(Q·K^T): Pesos de atención (qué tan relevante es cada posición)
  • √d_k: Factor de escala para estabilidad numérica

¿Por qué "Multi-Head"?

En lugar de aplicar atención una sola vez, aplicamos múltiples veces en paralelo. Cada "head" puede aprender diferentes aspectos:

  • Head 1: Relaciones a corto plazo en MFCC
  • Head 2: Patrones de media duración
  • Head 3-6: Otros patrones relevantes

Luego concatenamos todas las salidas: output = [head1, head2, ..., head6] · W_o

¿Qué son los MFCC y por qué extraerlos?

MFCC = Mel Frequency Cepstral Coefficients

Son características que representan el sonido de manera que refleja cómo lo percibe el oído humano:

  • Basadas en escala Mel (cómo oímos frecuencias)
  • Mucho más compactas que audio crudo (13 valores vs millones)
  • Capturan características relevantes para clasificación
  • Reducen ruido irrelevante

Sin MFCC, tendríamos que procesar audio crudo (22050 muestras/segundo), lo cual sería muy costoso computacionalmente.

¿Por qué conexiones residuales?

Las conexiones residuales (skip connections) son: x = x + f(x)

Ventajas:

  • Permiten entrenar modelos muy profundos (sin ellas, el gradiente desaparece)
  • Facilitan el flujo de información desde capas anteriores
  • Hacen que sea más fácil aprender perturbaciones pequeñas que mejoran la representación
  • Son especialmente importantes en Transformers (muchas capas apiladas)

¿Qué es Positional Encoding y por qué es necesario?

El mecanismo de atención es agnóstico al orden. Sin Positional Encoding:

  • [MFCC_t1, MFCC_t2, MFCC_t3] daría el mismo resultado que
  • [MFCC_t3, MFCC_t1, MFCC_t2]

Positional Encoding añade información de posición:

  • En este proyecto: pos_emb = torch.nn.Parameter(torch.zeros(1, 128, 128)) que se aprende
  • En BERT/ViT: funciones sinusoidales (sin y cos) de diferentes frecuencias
  • Resultado: el modelo sabe en qué posición temporal está cada frame MFCC

¿Cómo el modelo aprende a clasificar?

Proceso:

  1. MFCC (13D) → Embedding (128D) + Positional Encoding
  2. 2 Bloques Transformer: Cada uno tiene atención + MLP
  3. Mean Pooling: Promediamos la secuencia (128×128) → (128)
  4. Classification Head: (128) → (10 logits)
  5. Cross-Entropy Loss: Comparamos logits con etiqueta verdadera
  6. Backpropagation: Ajustamos pesos para minimizar pérdida

¿Qué es Dropout y cómo ayuda?

Dropout es una técnica de regularización:

  • Durante entrenamiento: desactiva aleatoriamente el 40% de neuronas
  • Durante evaluación: todas las neuronas están activas

¿Por qué funciona?

  • Evita que el modelo dependa excesivamente de conexiones específicas
  • Fuerza al modelo a aprender representaciones robustas
  • Actúa como un ensamble de sub-modelos
  • Reduce significativamente el overfitting

¿Diferencia entre LayerNorm y Batch Normalization?

LayerNorm: Normaliza cada muestra independientemente

  • Promediamos y normalizamos sobre las features (no sobre el batch)
  • Mejor para Transformers (mejor con batch sizes pequeños o variables)
  • No depende del tamaño del batch

Batch Normalization: Normaliza sobre el batch

  • Promediamos y normalizamos sobre las muestras del batch
  • Mejor para CNNs
  • Requiere batch size suficientemente grande

En Transformers usamos LayerNorm porque es más estable.

¿Cómo se manejan audios de duración variable?

El problema: Urban Sound 8K tiene audios de 4-30 segundos

La solución - Padding:

  • Fijamos longitud máxima: 128 frames (≈ 3 segundos a 22050 Hz)
  • Si audio es más corto: rellenar con ceros al final
  • Si audio es más largo: truncar a los primeros 128 frames

Ventajas: Batch processing es eficiente (todos tienen mismo tamaño)

Desventajas: Perdemos información de audios largos; padding con ceros puede no ser óptimo

¿Por qué Adam optimizer + Cosine Annealing?

Adam Optimizer:

  • Mantiene moving average del gradiente (momentum)
  • Mantiene moving average del gradiente² (adaptive learning rate)
  • Excelente para Transformers (mejor convergencia que SGD)
  • Learning rate inicial: 0.0004 (bajo para estabilidad)

Cosine Annealing Scheduler:

  • Reduce learning rate suavemente de forma coseno
  • Comienza en 0.0004, termina en 1e-6 después de 15 épocas
  • Permite exploración inicial, luego fine-tuning hacia el final
  • Mejor que decay lineal para convergencia

¿Qué es Early Stopping y cómo evita overfitting?

Early Stopping: Detiene el entrenamiento cuando la métrica de validación deja de mejorar

  • Monitoreamos val_loss en nuestro caso
  • Si no mejora en 8 épocas consecutivas, paramos el entrenamiento
  • Esto previene que el modelo memorice el conjunto de entrenamiento

¿Por qué funciona?

  • Fase 1: train_loss y val_loss bajan (aprendizaje)
  • Fase 2: train_loss sigue bajando pero val_loss sube (overfitting)
  • Early Stopping detiene en el punto óptimo (fin de fase 2)

¿Por qué Mean Pooling en lugar de otros métodos?

Alternativas y sus trade-offs:

  • Max Pooling: Toma valor máximo. Pierde información de contexto.
  • Mean Pooling: Promedia todos. Balanceado y simple. ✓ Mejor opción
  • Last Token: Toma último frame. Sesgado hacia final del audio.
  • CLS Token: Token especial (como en BERT). Requiere arquitectura especial.
  • Attention Pooling: Pesos aprendidos. Más complejo pero más flexible.

Elegimos Mean Pooling porque es simple, efectivo, y captura información de toda la secuencia de manera uniforme.

¿Cómo se evalúa el modelo después del entrenamiento?

Métricas principales:

  • Accuracy: Porcentaje de predicciones correctas en el conjunto de validación
  • Loss (Cross-Entropy): Mide la diferencia entre predicción y etiqueta verdadera

Interpretación:

  • val_acc > 90%: Excelente desempeño
  • val_acc 80-90%: Buen desempeño
  • val_acc 70-80%: Desempeño aceptable
  • val_acc < 70%: Necesita mejora

Pruebas adicionales (en producción):

  • Matriz de confusión: ¿Qué clases confunde el modelo?
  • Precisión y Recall por clase: ¿Es balanceado?
  • Robustez a ruido: ¿Funciona con audios ruidosos?

¿Cuáles son las principales limitaciones del modelo?

Limitaciones técnicas:

  • Padding/Truncating: Perdemos información de audios muy largos
  • Dependencia de longitud fija: No puede procesar audios de longitud arbitraria
  • Costo computacional: Multi-head attention es O(n²) en memoria

Limitaciones de datos:

  • Dataset pequeño: 8,732 muestras (poco para deep learning)
  • Desbalance de clases: Algunas clases más frecuentes que otras
  • Sesgo geográfico: Sonidos de solo 10 ciudades

Posibles mejoras:

  • Data augmentation (time stretching, pitch shifting)
  • Usar modelos pre-entrenados (transfer learning)
  • Arquitectura recurrente para manejar longitudes variables
  • Ensemble de modelos

📐 Matemáticas Clave

1. Scaled Dot-Product Attention

Attention(Q, K, V) = softmax(Q·K^T / √d_k)·V

  • Q·K^T produce similitud entre queries y keys
  • Dividir por √d_k es crucial para estabilidad (gradient flow)
  • Softmax convierte similaridades en probabilidades
  • Multiplicar por V da la salida ponderada

2. Multi-Head

head_i = Attention(Q·W_Q^i, K·W_K^i, V·W_V^i)

MultiHead(Q,K,V) = Concat(head_1,...,head_h)·W^O

3. Feed-Forward Network

FFN(x) = ReLU(x·W_1 + b_1)·W_2 + b_2

Típicamente: d_model → 4×d_model → d_model (en nuestro caso: 128 → 512 → 128)

4. Cross-Entropy Loss

L = -Σ_i y_i · log(p_i)

Donde y_i es la etiqueta (one-hot) y p_i es la probabilidad predicha

5. Adam Optimizer

m_t = β₁·m_{t-1} + (1-β₁)·g_t (1st moment)

v_t = β₂·v_{t-1} + (1-β₂)·g_t² (2nd moment)

θ_t = θ_{t-1} - α·m_t / (√v_t + ε)

Categoría Parámetro Valor Impacto
Arquitectura n_heads 6 Más heads = más capacidad expresiva pero más parámetros
n_layers 2 Más capas = puede capturar dependencias más complejas
n_embd 128 Dimensión del espacio latente. Más = más capacidad
Aprendizaje learning_rate 0.0004 Controla velocidad de convergencia. Bajo = estable pero lento
weight_decay 5e-4 Penaliza pesos grandes. Aumenta = menos overfitting
dropout 0.4 Probabilidad de desactivar neurona. Aumenta = menos overfitting

Definiciones Importantes

  • Embedding: Proyección lineal que mapea datos a un espacio de mayor dimensión donde patrones son más fáciles de aprender
  • Query, Key, Value: Las tres proyecciones del mecanismo de atención que permiten al modelo relacionar información
  • Residual Connection: x = x + f(x). Permite que el gradiente fluya directamente a través de capas
  • Layer Normalization: Normaliza features de cada muestra independientemente. Estabiliza entrenamiento
  • Dropout: Desactiva aleatoriamente neuronas. Reduce co-adaptación y overfitting
  • Cross-Entropy Loss: Mide diferencia entre distribución predicha y verdadera. Estándar para clasificación
  • Accuracy: Porcentaje de predicciones correctas. Métrica principal para evaluación
  • Mean Pooling: Promedia features sobre una dimensión. Reduce dimensionalidad

📝 Resumen Ejecutivo

¿Qué Hicimos?

Implementamos un Transformer Encoder para clasificar automáticamente sonidos urbanos del dataset Urban Sound 8K en una de 10 categorías diferentes.

¿Cómo Funciona?

  1. Extraemos características MFCC de archivos de audio (.wav)
  2. Normalizamos y hacemos longitud fija mediante padding
  3. Pasamos por 2 Bloques Transformer con Multi-Head Attention (6 heads)
  4. Hacemos Mean Pooling para obtener un embedding único
  5. Clasificamos en 10 clases mediante un MLP

¿Por qué Transformers?

  • Atención global: Cada frame MFCC puede relacionarse con todos los demás
  • Paralelización: Procesa toda la secuencia simultáneamente
  • Multi-Head: Captura múltiples aspectos del audio
  • Estado del arte: Mejor que CNNs para este tipo de datos

Ventajas del Enfoque

✓ Paralelizable ✓ Escalable ✓ Interpretable (atención) ℹ️ Estado del arte ⚠️ Requiere normalización

Mejoras Futuras

  • Data Augmentation: Time stretching, pitch shifting
  • Arquitectura Recurrente: Manejar longitudes variables
  • Explainability: Visualizar qué aprende el modelo
